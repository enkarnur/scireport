# 文研智库 MVP 交互设计

## 1. 产品边界与核心原则

- 面向 Windows / Mac 的本地优先文献管理：PDF 文件不上传后端，浏览器本地完成选取、文本提取与基础元数据识别。
- 后端仅接收用户确认后的提取文本、页级定位信息和元数据，使用 SQLite 保存论文、结构化内容、批注、问答记录与报告。
- 不依赖 GitHub Token，不读取、保存或传输任何用户凭据。
- 主界面采用双工作区：左侧为 PDF 文献工作区，右侧为交互 / 报告工作区；窄屏时切换为分栏页签。
- 结构化内容固定覆盖摘要、研究背景、方法、结果、讨论五部分；无法提取的部分返回空值与处理状态，不伪造内容。
- 问答与报告必须附带命中文献和定位线索（页码、章节、文本片段），便于用户回到原文核验。

## 2. 真实业务路由规划

| 路由 | 稳定任务 | 页面职责与主操作 | 关键状态 |
|---|---|---|---|
| `/library` | 管理文献库 | 选择 PDF；浏览器本地提取文本；确认元数据并入库；搜索、筛选、删除论文 | 初次空状态、提取中、入库中、解析中、解析失败、列表/筛选无结果 |
| `/papers/:paperId` | 阅读与研析单篇论文 | 左侧显示本地 PDF 或页级提取文本并定位；右侧查看结构化摘要、批注列表；新增、编辑、删除、检索和跳转批注 | PDF 本地句柄缺失、论文加载中、批注筛选、定位页码/文本片段、结构化处理中 |
| `/ask` | 在文献库范围问答 | 输入问题；选择全部文献或指定论文；展示答案、命中文献与可点击定位线索；保留近期问答 | 空问题、无可用论文、生成中、无命中、答案与证据、失败重试 |
| `/reports` | 生成与管理系统文献汇报 | 选择模板和论文范围；生成报告；浏览历史报告、查看详情、导出 Word | 生成中、历史为空、报告详情、导出中、导出失败 |
| `/reports/:reportId` | 查看单份报告 | 展示模板化章节、引用论文与定位线索；触发 Word 导出 | 加载中、生成中、完成、失败、导出就绪 |
| `/` | 默认入口 | 重定向到 `/library` | 无 |

## 3. 交互触点表

| 触点 | 触发方 | 行为 | 结果 / 联动 | 数据刷新 |
|---|---|---|---|---|
| PDF 本地导入 | 人 / Web UI | 选择 PDF，在浏览器提取全文与页级文本；用户确认标题、作者、年份等元数据后调用论文入库 API | 入库成功后进入 `/papers/:paperId`；原 PDF 保留在用户设备，后端仅保存提取结果 | 前端直接更新文献列表与详情状态 |
| 结构化研析 | Service | 论文入库时基于提取文本形成摘要、背景、方法、结果、讨论及状态 | 详情页持续展示处理状态；完成后可用于问答与报告 | 前端轮询详情；后续可替换为任务事件 |
| 文献库问答 | 人 / Web UI；Agent / Skill | 选择文献范围并提交问题 | 返回答案及 `citations`；点击线索打开 `/papers/:paperId` 并定位页码/章节/片段 | 前端提交后追加本次问答；Skill 写操作由生成客户端通知 `qa` |
| 批注管理 | 人 / Web UI；Agent / Skill | 在当前页或文本选区创建批注；按关键词、论文和页码检索；编辑或删除 | 点击批注定位到对应论文页码和高亮片段 | 前端操作后局部更新；Skill 写操作自动通知 `annotations` |
| 系统文献汇报 | 人 / Web UI；Agent / Skill | 选择模板、标题、论文范围并生成报告 | 返回报告记录；打开 `/reports/:reportId` 查看章节、引用和生成状态 | 前端生成后更新历史；Skill 写操作自动通知 `reports` |
| Word 导出 | 人 / Web UI；Agent / Skill | 对已完成报告请求 DOCX 导出 | API 返回文件名、MIME 类型与 Base64 内容；前端在本地组装 Blob 下载 | 不改变核心业务数据，仅更新导出反馈 |
| Agent 操作文献库 | Agent / Skill | 使用生成的 typed Python client 查询论文、检索批注、发起问答或报告 | Agent 在对话中总结结果，并可引导用户打开对应业务路由 | 所有非前端写操作由生成客户端统一 `notify_refresh(resource)` |

## 4. 左右工作区联动

- `/papers/:paperId`：左侧 PDF / 文本阅读器维护当前页码与选区；右侧结构化内容、批注点击后反向驱动左侧定位。
- `/ask`：右侧答案中的引用线索点击后打开论文详情，并携带 `page`、`section`、`quote` 作为定位上下文。
- `/reports/:reportId`：报告章节引用点击后进入对应论文详情，定位到证据页与片段。
- 页面需要 Agent 协助时可使用 `window.__aime__.sendPrompt()` 发送“基于当前论文继续追问 / 生成报告”等指令；Agent 可通过 Skill 调用同一组 Service API。
- 若后续增加 inline 卡片，卡片只展示问答或报告完成摘要，并通过 `openApp({ location: { path } })` 打开 `/ask` 或 `/reports/:reportId`；卡片不直接调用鉴权 API。

## 5. API 与后续并行开发边界

- **前端 Agent**：只使用生成的 `client.gen.ts`；浏览器承担 PDF 读取、文本提取、页级切分及 DOCX Base64 下载落盘。
- **后端 Agent**：实现论文、批注、问答、报告与导出的 handler；使用 SQLite；统一成功响应为 IDL 中的 JSON 契约，错误响应为 `{ "error": "message" }`。
- **集成层 Agent**：使用生成的 `api_client.gen.py`；为 Agent 暴露文献查询、批注检索、知识库问答和报告生成能力；不保存凭据。
- **删除语义**：删除论文时级联删除其批注，并从问答 / 报告后续检索范围中排除；历史报告可保留其生成时快照和引用线索。
- **定位契约**：页码从 1 开始；`section` 为章节名；`quote` 为短文本片段；`startOffset` / `endOffset` 是提取全文中的字符偏移，可为空或为 0。
